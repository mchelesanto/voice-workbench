# Vocabulary editor

The global dictionary uses a reusable controlled chip editor. One chip is one word or phrase; internal spaces remain part of that phrase. The shared dictionary limit is 1,000 terms from LIMITS. Provider-specific request caps and future area scope follow `workspace-management.md`; alphabetical display never truncates a list to fit a provider.

Display uses an English, numeric, case-insensitive Intl.Collator with a variant-sensitive tie-breaker. Only a copy is sorted. Rendering preserves saved input order and provider payloads. Settings conflicts compare normalized term sets: the same words in a different stored order already satisfy the requested vocabulary, so the canonical server version is adopted without asking the user to resolve an invisible difference. Case/spelling changes remain real conflicts. Existing shared validation remains authoritative: trim, NFC, exact deduplication, up to 80 characters per term and no commas/control characters. The installed Zod length check counts Unicode code points; the UI does not impose a stricter UTF-16 cap. Forbidden characters are checked on the raw segment before trimming, using the same predicate as the shared schema. Canonical terms are then normalized and validated before sending.

Enter, comma or Add commits pending input, except during IME composition. Comma, newline and tab delimit bulk paste; spaces do not. Paste replaces the current input selection and preserves its prefix/suffix. Valid terms become chips; rejected entries remain editable with an explanation. Capacity overflow never silently truncates the list. Removal has a labeled button and returns focus to the input. A bounded scrolling tag list keeps the input reachable and explicitly indicates when more terms can be scrolled into view. Empty vocabulary is valid.

Save is enabled only for a meaningful change. It commits the final pending phrase, then submits the existing revision-checked settings write. Unresolved rejected input blocks the request. A pending duplicate is cleared locally without sending a no-op settings write. A synchronous guard prevents overlapping saves; editing and dismissal are blocked until the request settles. Success and matching replay use the canonical returned settings. Errors retain the local terms. A conflict has its own view, receives focus, and replaces the ordinary Save footer with two explicit choices. Review terms returns to the preserved editor with the returned revision, requiring another Save; choosing the other version requires confirmation and updates both the local draft and workspace settings immediately. Failed or conflicting requests do not claim success.

Closing a changed editor asks before discarding; pending non-whitespace input counts as a change. Browser navigation warns while dirty or saving, without claiming guaranteed recovery after reload. Successful saves update the workspace settings used by subsequent transcription. A panel opened before the initial settings response remounts when that first usable response arrives; no editable draft is lost because the waiting panel was disabled. Models remain inspectable in a disclosure beneath the editor. The footer is separate from scrolling content, including on short mobile viewports.
