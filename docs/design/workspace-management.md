# Areas, vocabulary chips, temporary audio, and clearing the library

Status: approved contract. The M2 client implements the persistence and lifecycle foundation, including temporary audio and General capture. Area-management, destination/filter/move controls, and the delete-all entry screen are M3. The foundation is locally validated. Migration is explicit; normal upgrades preserve existing notes and earlier audio.

## Confirmed product behavior

Areas organize both notes and vocabulary. Each capture/import uses global words plus the selected area's words. Words are displayed as alphabetically ordered editable chips, not one term per textarea line. Delete all removes all cloud notes and content in the initiating browser profile, preserving global vocabulary, areas, and area vocabulary. It does not physically purge another browser profile or computer.

New audio is memory-only for the lifetime of its tab. Closing or reloading that tab loses audio; changing the selected note inside the app does not. A successful transcript, note edits, and vocabulary remain persistent once their respective storage transaction confirms. A storage failure keeps exportable RAM text and never claims durability. Imported original files and manually downloaded copies are outside application cleanup. Do not implement persistent audio plus an unload-time delete job: browser-close callbacks are not reliable.

## Audio and text lifecycle

1. Capture or explicit import submission freezes `{id, generation, areaId, areaLabel, vocabulary, provider, mode, createdAt}`. The Blob remains in an in-memory per-tab recording map only. No audio bytes in IndexedDB, local/session storage, Cache API, service workers, or server files. Durable text writes pass a strict text-only runtime schema before put, rejecting extra Blob/audio fields, not merely a TypeScript type.
2. Transcription may begin from this explicitly temporary audio without pretending there is a durable backup. Provider/model retries remain manual. A per-recording attempt token and tab lifecycle token reject late completions after discard, reset, or replacement. There is no cross-tab audio CAS, because tabs do not share audio.
3. On response, construct a text-only Draft and secure it in IndexedDB before attempting cloud creation. Do not include a Blob, an audio byte string, or the RAM recording object in any durable draft. If local text storage fails, keep text visible in RAM for copy/download, with no success claim. The cloud save uses the existing UUID and conflict/replay rules.
4. Audio remains playable/downloadable while its tab is alive, including after a failed or canceled model request. Label: `Audio is temporary in this tab. Closing or reloading removes it.` The library on another computer never claims audio availability.
5. During initial processing show `Audio ready in this tab`, not `Audio saved on this device`. The first visual step means capture preparation, not local audio persistence. A completed text may truthfully show `Transcript saved on this device` after its draft transaction commits. Refine and note storage do not change audio retention.
6. Unmount/discard releases tracks, AudioContext, player and object URLs; pagehide performs synchronous best-effort cleanup. Correctness depends on never persisting audio, not on that event. Warn before leaving while capture/model work is running, while text is not durably secured, or while a non-discarded RAM recording has no confirmed text draft/cloud note. This includes ready, canceled and failed audio. Once its text is confirmed in IndexedDB or cloud, audio alone does not trigger a close warning. Leaving despite a warning still drops RAM audio; the warning is not a retention guarantee.

**RAM capacity:** Retain multiple recordings with an explicit total Blob-byte budget of twice the largest supported single-file upload (currently 1,000,000,000 bytes). Before microphone permission, reserve the selected provider's maximum upload size; before import inspection reserve the known file size. If retained blobs plus the reservation exceed the budget, offer download/remove of existing temporary audio before starting. No time cap, silent eviction or automatic removal of failed audio. Reservations are owned by unique operation tokens. Release only the matching token: unused reservation when capture completes and all reservation on cancellation, never a newer operation's reservation from a late callback. Show count/retained bytes in the temporary-audio panel. This bounds retained Blob bytes, not total browser heap. If a late native chunk exceeds the reservation, retain the captured salvage audio, stop, and block further additions until explicit cleanup; never discard captured speech to meet the budget.

**Legacy audio:** IndexedDB upgrade preserves old Recording rows read-only. Metadata has `legacyAudioTransition:'pending'|'complete'`; pending tracks retained audio only and never blocks new capture/import. Existing audio and drafts remain accessible in Local audio & drafts, without a separate availability banner or mandatory cleanup. New code never writes a fresh legacy audio row. Legacy rows have a minimal parser for their existing key, Blob, optional result and snapshot identity. A metadata entry `legacy-result:<recordingId>` stores a generated `extractedDraftId`; result extraction writes that mapping and one text-only draft in the same records+metadata transaction. A repeated extraction reuses the mapping and never creates another draft. A confirmed-cloud result is a confirmed local copy if its current note can be verified; otherwise it is a read-only recovered text copy, not an automatic cloud write.

An explicit legacy Remove validates the exact legacy snapshot, secures any unextracted result as text and deletes the audio row in the same transaction. A failure leaves the old audio in place. Already extracted text is never overwritten; if its copy was deliberately removed, do not resurrect it on reload. Rows without a result need only explicit audio-removal confirmation. Download never counts as deletion. Mark transition complete only in a committed transaction that finds no remaining legacy audio. Own-profile delete-all explicitly includes earlier saved local audio and can clear it without extraction, because that loss is confirmed. No upgrade or remote reset silently purges these files.

## Vocabulary chips

One chip represents one word or phrase, including internal spaces. Display is sorted using `Intl.Collator('en', {sensitivity:'base', numeric:true})`, with a variant-sensitive comparison as the tie-breaker. Sort a copy for display; do not mutate saved order or the frozen provider payload merely by rendering.

Use a labeled input with Add, Enter, and comma to commit a term. IME composition is never committed prematurely. Multiline/comma/tab paste splits terms; ordinary spaces do not. Paste respects the current selection/caret. Save also commits valid unfinished input, so a typed last word is not lost. Invalid terms remain editable with a local error; a bulk paste cannot silently drop rejected items. Each chip has a keyboard-accessible `Remove <term>` button. Editing is optional through removing/re-adding; no opaque keyboard-only interaction is required. Show term count, alphabetical ordering, and effective global-plus-area count. Reuse one editor for both global and area words. Bound the chip-list scroll region; keep adding/saving reachable with a large list. On small screens use a labeled scope selector instead of clipped area tabs, and make inherited global words collapsible.

Canonical stored term: trim and NFC, 1..80 Unicode code points, no commas or control characters. Exact-string deduplication preserves intentional spelling/case variants. Global and individual area lists allow up to 1,000 terms, matching the largest current provider vocabulary capacity. Effective vocabulary is the stable exact-string union, globals first. A separate request schema validates provider caps, Google 1,000 and Mistral 100, published through `/config.providers[].maxVocabularyTerms`. The multipart vocabulary field allows at most 512 KiB of UTF-8 JSON, within the existing 1-MiB multipart overhead reserve, so valid merged multilingual lists do not hit the previous smaller field cap. Excess blocks a new model request with the actual count; never silently drop global or area words.

Global words are shown as inherited/read-only inside an area, with a direct route to the single global editor. Saving a list uses revision CAS and preserves a conflicting local version. Closing with changed chips or unfinished input asks before discarding edits.

## Areas and note organization

An area is a flat personal project, not a tenant or permission boundary. Existing notes migrate to General (`areaId:null`). Area CRUD: create, rename, edit words, archive, restore. No destructive area deletion in this increment. Archived areas remain readable on old notes; an already frozen capture may finish in an archived area. Archive removes a choice from newly refreshed capture pickers, not a permission to persist earlier work. Refresh settings and the selected area context before freezing a new online context (General requires settings only); a race after that snapshot is intentionally accepted. Offline capture may explicitly use the last loaded area/words. That frozen snapshot can later be submitted unchanged if library generation still matches, even if words changed or the area was archived meanwhile. Show this cached-context condition rather than silently rebinding it.

Name canonicalization is `raw.trim().normalize('NFC').replace(/\s+/gu, ' ')`, 1..80 UTF-16 units; stored `name_key = name.toLowerCase()`, independent of browser locale. A partial unique index over name_key where archived_at IS NULL enforces create/rename/restore uniqueness. Conflict is `area_name_conflict`, no implicit rename.

Library filtering and next-recording destination are explicit, separate state. `All notes` is a library filter, not an area. The recording/import control always shows its chosen destination, including General. Opening an older note never retargets the next capture or its vocabulary.

A note can be explicitly moved by a revision-checked update without retranscription. `areaId` is therefore organizational mutable metadata alongside title/body. A Recording's capture-area/vocabulary snapshot stays frozen while that RAM recording exists. Note create-replay compares the existing immutable origin (original text, provider, model, mode, duration) plus generation. It never overwrites a newer title, body, or area. A replay whose requested title/body/area differ from the returned current note is a visible conflict, not permission to move the note back.

## SQL persistence and legacy servers

Add a numbered migration, never edit 0001. Introduce:
- `areas(id, name, name_key, vocabulary_json, revision, created_at, updated_at, archived_at, creation_digest)`. The digest is the lowercase hex SHA-256 of UTF-8 `JSON.stringify([canonicalName, canonicalVocabulary])`, computed by one server function and never changed. Canonical vocabulary preserves normalized input order, not alphabetical display order. It makes area-create replay work even after a rename/vocabulary edit/archive.
- `library_state(id=1, generation, last_reset_at)`, positive safe integer generation, initial 1.
- `library_resets(operation_id PRIMARY KEY, from_generation, state, to_generation, reset_at, deleted_note_count)` with no note text/audio. state is completed or cancelled; completed requires target generation/timestamp/count, cancelled stores only the claimed source generation and no deletion result.
- New physical `library_notes` with the existing note fields plus required generation with **no runtime default**, and nullable area_id. Copy existing notes at generation 1, preserve every ID, timestamp and revision, and recreate indexes/origin/no-recreation constraints for the new table. Before dropping the old table, assert equal row counts and field-by-field equality for every original ID, including timestamps/revision, inside the same migration transaction; a mismatch aborts the migration through a temporary CHECK-assertion table, not a top-level RAISE expression (which SQLite only permits in a trigger). Tests cover empty/nonempty data and deliberate rollback after copy.

Replace the old `notes` table name with a read-only compatibility view. No INSTEAD OF write triggers. The current legacy Store's INSERT, UPDATE and DELETE against `notes` must fail against the migrated database, verified using those actual SQL statements. New Store writes only `library_notes`. Thus an old server on another computer cannot bypass the new API generation check. Old installations need updating; no automatic update of their frontend/audio-retention policy is promised.

Every new note mutation compares request generation to library_state inside the same write transaction. A database INSERT guard also requires the note generation to equal the singleton; generation and immutable note origin cannot change on UPDATE. Resolve a non-null area_id under the same write transaction and require an existing area (archived is allowed). Note title/body/area remain revision-checked mutable fields. Keep per-note deletion markers; reset inserts markers for deleted note IDs before deleting note content, preventing ID reuse from reviving an old note. Markers and reset receipts are minimal operational metadata, not retained note content.

Note reads/listing use one read transaction or one SQL statement for library_state, generation validation, and content. Never label an old read with a new generation from a separate query. Contended `BEGIN IMMEDIATE` may fail with SQLITE_BUSY; the contract does not promise waiting. Map it to a safe storage error. Include new tables in schema-unavailable diagnostics.

## Cloud reset protocol

The confirmed scope is all notes in every area, plus local content of the initiating browser profile. Global/area vocabulary and their revisions are untouched. Reset is one write transaction:
1. Find operation receipt first; different expectedGeneration under the same ID -> reset_conflict. A matching completed receipt replays unchanged; a matching cancelled receipt -> reset_cancelled before any deletion.
2. Require expectedGeneration == current generation and current < MAX_SAFE_INTEGER. Otherwise fail before deletion.
3. Add note-ID markers, delete library_notes, increment generation, set reset timestamp, insert receipt, commit.

Writes before reset may commit and are included; stale writes after reset fail with library_reset. A receipt replay never deletes post-reset content. A receipt is historical, not necessarily the latest library state; reconcile current state after replay before unlocking. No automatic reset retry. A timeout/storage error can have an unknown commit outcome, so the explicit retry uses the same recorded operation ID/body. A GET reporting unchanged state is not proof that an earlier reset cannot still commit.

A prepared journal can always offer `Resolve / stop this reset` once the server is reachable. `POST /api/library/reset/cancel` takes the same operationId/expectedGeneration. In one write transaction, a matching completed receipt wins and is returned; an existing cancelled receipt replays cancellation; absence inserts a cancelled receipt without deleting notes or advancing generation. A delayed reset with that ID subsequently sees cancellation and cannot commit. Different input under the ID -> reset_conflict. A matching authoritative cancelled outcome authorizes local journal release without a local clear, followed by current-state reconciliation; the strictly matched reset_cancelled response and the explicit conflicting-ID repair case are defined below. Network/validation/configuration failures, including ones on a later attempt after an unknown result, never constitute proof that an earlier request did not commit. Keep the claim and exports available until same-ID replay/cancel resolution succeeds. A previously acknowledged journal never uses this cancel route; it resumes local cleanup only.

## Local text persistence, reset journal and reconciliation

IndexedDB v2 keeps a records store for text drafts/legacy rows and a metadata store. Metadata: `{profileId:UUID, observedGeneration:SafeInt, initialized:boolean, pendingReset:null|{operationId,expectedGeneration,phase:'prepared'|'acknowledged',receipt?:ResetReceipt}, completedLocalResetId:UUID|null, legacyAudioTransition:'pending'|'complete'}`. New durable records are text-only Drafts with required generation in their input. Legacy v1 text is explicitly migrated as generation 1/General, never defaulted to the currently observed generation. Unknown/corrupt records are quarantined, not silently adopted or deleted on remote reconciliation. Listing may assign a missing quarantine token atomically while no reset is pending; it never rewrites the content. Unknown raw payloads are not retained in UI state.

Preparing reset is a readwrite transaction over records + metadata: claim pendingReset only if none is present. A second tab resumes the existing operation or stays blocked; it cannot replace its ID. A synchronous single-flight guard precedes the first await in the UI. Every ordinary current-content mutation opens both stores, verifies record generation == metadata generation and pendingReset == null, then performs its mutation within the IDB request chain. Two narrow exceptions are defined below, historical preservation and delete-only archive removal. They never promote content to the current generation. No unrelated awaits inside an active IDB transaction. Report success only at transaction.oncomplete. A blocked database upgrade prevents starting reset.

While pendingReset exists, all tabs of that profile block capture/import/edit/restore and new local/cloud content writes. Existing work is quiesced, not silently recast into a new generation. BroadcastChannel accelerates discovery; metadata checks enforce the lock. A prepared operation with unknown outcome stays locked across reload and offers explicit retry of exactly that request. Do not let a local error re-enable old sessions.

After receipt acknowledgement, store its phase/receipt; terminally invalidate content contexts and abort requests. One local transaction, conditional on the same pending operation ID, clears this profile's records (including legacy/invalid local content explicitly covered by confirmation), clears pendingReset, sets completedLocalResetId, and monotonically updates observedGeneration. Current-profile writes have been blocked since preparation, so no permitted post-reset record can be swept by this clear. Duplicate/old callbacks whose pending ID no longer matches **never clear records again**. They can only request reconciliation. Resume an acknowledged operation with local-only cleanup, not another cloud reset. A cleanup failure leaves the profile locked with `Cloud cleared; device cleanup pending`.

A 409 library_reset means a different reset won, but does not itself release the prepared journal. Keep the same operation ID/body and resolve through `/api/library/reset/cancel`: completed means apply that receipt's local cleanup; cancelled means CAS-release only that exact journal without clearing records, then reconcile. Never rewrite expectedGeneration or submit a fresh reset automatically. If the user still wants a new delete-all afterward, a new confirmation is required.

A reset_cancelled response from the exact pending reset request is also an authoritative cancellation, because its server branch runs only after matching both operation ID and expected generation to an immutable cancelled receipt. Return that matching ResetResolution in the reset conflict variant below; it authorizes the same conditional journal release and reconciliation as a 200 cancelled response from the cancel endpoint. No second cancel request is required. Other errors are not cancellation proof. A reset_conflict includes the immutable existing outcome; a different stored source generation proves this request body never committed under that ID. Offer explicit release of this exact conflicting local claim without cleanup, never apply a mismatched completed receipt as if it belonged to this request. Generation overflow is `generation_exhausted`, with no deletion.

**Other browser profiles/computers:** a higher remote generation removes stale cloud notes from the active library and fences old content writes. It does **not physically delete their local text/legacy audio or live RAM audio**. Old local material becomes a clearly labeled read-only previous-library archive with copy/download/remove actions. No auto-restore, provider retry, new-ID duplication or generation promotion. A new explicit import can use downloaded audio under a fresh UUID/current context. This preserves offline material created after a reset elsewhere without trying to infer global order from device clocks.

On startup: open metadata, resolve pending reset first, fetch library state, reconcile, then publish library/current-generation recovery. Settings/areas may load independently. If offline, retained material may be export-only; new recording can remain RAM-only with the last known context, but cannot automatically send or persist after a generation mismatch. If no prior generation/context is known, require successful initialization first. Reconcile on visibility, manual refresh, before any model call/restore, and every 30 seconds while visible, including during editing/recording. At most one reconciliation is in flight.

One central client controller owns terminal content invalidation. It invalidates editor queues, delayed open/list/local-read tickets and refine proposals, aborts model/data requests, and prevents late result publication. On a local-profile reset completion it also discards RAM audio and releases media resources in all same-profile tabs. On a remote-only reset it fences but retains RAM audio for download, and moves old text to read-only access. Vocabulary editors and unsaved word edits are independent and are not discarded by this operation. No generic error handler treats library_reset as an ordinary retryable save error.

## Local reset marker and remote preservation

Each tab holds a fence `{generation,completedLocalResetId}` independent of shared metadata. On BroadcastChannel, pageshow, visibility/focus, before publishing retained content and before every audio action, reconcile that fence with metadata. A changed completedLocalResetId identifies a same-profile clear: terminally invalidate the tab, discard old RAM audio, release media resources, and suppress late callbacks. A generation change without a changed local-reset marker identifies a remote-only clear: fence old cloud writes but retain local copies. A sleeping tab must perform this check before re-exposing its old audio or handling playback/download; comparing only remote generation with shared metadata is insufficient. Do not claim immediate physical erasure inside a frozen tab. Completion copy confirms cloud, committed local storage and this tab; other open tabs discard old audio on their next execution.

For a remote-only clear, synchronously freeze editor mutation and capture the newest live text snapshots before invalidating queued work. A dedicated records+metadata reconciliation transaction saves those exact snapshots with their original generation as read-only `previous_library` drafts, then monotonically advances metadata. This historical preservation is allowed even if another tab has already advanced observedGeneration: require the captured old tabFence, unchanged completedLocalResetId, no pendingReset, old snapshot.generation < metadata/remote target, and no current-key overwrite. Capture a stable UUID snapshotToken once per frozen editor snapshot and store under an archive-specific key derived from it; repeating the operation reuses that token. Existing current records and older stored snapshots are untouched. A local reset marker change overrides historical preservation and discards the old snapshot. Ordinary current writers never receive this exception. It cannot change note ID/generation or call cloud writes. Ordinary stale persist callbacks remain rejected. If that transaction fails, keep the newest snapshot exportable in RAM, stay fenced and do not claim durability. Every retry invalidates any new old-generation contexts created since the failure; pending historical snapshots are not evidence that no new capture exists. An unchanged reconciliation does not rewrite metadata. Existing previous drafts without a live replacement remain intact.

A remote-only clear during microphone capture uses `quarantineAndStop()`: finish native chunks, release tracks/meter, retain a read-only Blob with its old snapshot, and never invoke the automatic transcribe callback. Permission still pending is cancelled/released when it arrives. Native onstop rechecks the tab/local-reset fence before publishing the quarantined Blob; a local clear arriving while stop completes wins and discards it. Own-profile clear uses discard, not quarantine. In-flight model/refine calls are aborted; late outputs cannot revive a context. Completed visible RAM text is included in the frozen historical snapshot; audio remains downloadable until the tab ends.

`removeArchived(expectedKey,expectedGeneration,expectedSnapshot)` is a dedicated delete-only records+metadata transaction. It requires no pending reset, an exact value-based match to the displayed record snapshot (not JavaScript object identity) and record.generation < observedGeneration. It cannot put/promote/change any record or delete a current-generation row. Unknown/corrupt quarantined rows require an explicit per-item removal of that exact raw snapshot; they never pass a current-content writer. Success is transaction.oncomplete.

## Complete wire contract

UUIDs, timestamps, note/string limits, revision semantics, Host/Origin guard and safe error envelopes retain their existing definitions. `SafeInt` is an integer 1..Number.MAX_SAFE_INTEGER. Strict objects reject unknown fields.

```ts
type LibraryState = { generation: SafeInt; lastResetAt: ISODate | null };
type ResetReceipt = { operationId: UUID; fromGeneration: SafeInt; generation: SafeInt; resetAt: ISODate; deletedNoteCount: SafeNonNegativeInt };
type Area = { id: UUID; name: string; vocabulary: string[]; revision: SafeInt; createdAt: ISODate; updatedAt: ISODate; archivedAt: ISODate | null };
// Existing Note fields stay identical, plus:
type NoteContext = { generation: SafeInt; areaId: UUID | null };
type NotePage = { generation: SafeInt; items: (ExistingNoteSummary & NoteContext)[]; nextCursor: string | null };
type Conflict =
  | {kind:'note'; current: ExistingNote & NoteContext}
  | {kind:'settings'; current: Settings}
  | {kind:'area'; current: Area}
  | {kind:'library'; current: LibraryState}
  | {kind:'reset'; current: ResetResolution};
type ManagementErrorCode = 'library_reset'|'reset_conflict'|'reset_cancelled'|'generation_exhausted'|'area_name_conflict'|'area_not_found';
type Failure = { error:{code:ExistingErrorCode|ManagementErrorCode;message:string;issues?:FieldIssue[]}; conflict?:Conflict };
type ResetResolution = {state:'completed';receipt:ResetReceipt}|{state:'cancelled';operationId:UUID;expectedGeneration:SafeInt};
```

- `GET /api/library-state` -> LibraryState.
- `POST /api/library/reset` `{operationId,expectedGeneration,confirmation:'DELETE ALL NOTES'}` -> ResetReceipt, always 200 on initial success/replay. No implicit retry.
- `POST /api/library/reset/cancel` `{operationId,expectedGeneration}` -> ResetResolution, 200. No content deletion. Only an authoritative cancelled outcome releases an unacknowledged local claim without clearing content.
- `GET /api/areas` -> `{items:Area[]}`, including archived.
- `PUT /api/areas/:id` `{name,vocabulary}` -> Area, 200. Compare immutable creation_digest before replay; replay never renames, rewrites vocabulary or unarchives. Other input -> 409 id_conflict with area conflict.
- `PATCH /api/areas/:id` `{name,vocabulary,archived:boolean,expectedRevision}` -> Area, 200. All fields required; revision CAS. Duplicate active name -> 409 area_name_conflict. Missing area -> 404 area_not_found.
- `GET /api/notes?generation=N&area=all|general|UUID&cursor=...` -> NotePage. generation required, area defaults all. Cursor v2 is canonical base64url JSON `{v:2,generation,area,updatedAt,id}`, max 512 characters. Filter mismatch/malformed cursor -> invalid_input, stale generation -> library_reset, including empty results.
- `GET /api/notes/:id?generation=N` -> ExistingNote & NoteContext. Validate generation in the same read snapshot before 404/410, so reset is not confused with a single-note delete.
- `PUT /api/notes/:id` existing CreateNote fields plus `{generation,areaId}` -> contextual Note. Immutable identity includes generation; title/body/area changes never overwrite an existing note on replay.
- `PATCH /api/notes/:id` `{title,body,areaId,expectedRevision,generation}` -> contextual Note. All fields required.
- `DELETE /api/notes/:id` `{expectedRevision,generation}` -> 204. A single-note delete clears its current local editor and matching temporary audio; earlier saved legacy audio remains in its separate explicit cleanup flow. Other single-note rules remain unchanged.
- `POST /api/transcribe` existing multipart fields plus required canonical integer `generation`. Provider-specific effective vocabulary validation and generation preflight before the billable provider call. Keep the existing model slot around bounded body parsing to retain memory/concurrency bounds. Response adds generation; client requires equality with its captured context.
- `POST /api/enhance` `{text,preset,generation}` -> existing response plus generation. Same generation preflight and terminal apply guard. A reset may still occur after preflight and cannot undo provider costs.
- `GET/PUT /api/settings` remains revisioned global vocabulary outside the library generation.

New error statuses: library_reset, reset_conflict, reset_cancelled, generation_exhausted and area_name_conflict are 409; area_not_found is 404. library_reset includes `{kind:'library',current:LibraryState}`; reset_cancelled and reset_conflict include the immutable matching/existing `{kind:'reset',current:ResetResolution}` outcome; CAS area conflicts include the current Area. A name collision returns a safe fixed message without requiring an arbitrary matching Area payload. Reset errors never enter ordinary automatic retry. `reset_pending` is a local coordinator error only, not a server failure code. Existing storage/timeouts keep their established status codes.

All content API callers use the discriminated conflict union, never overlapping property sniffing. Requests without mandatory generation fail before content effects, never default to current. Existing old servers are additionally blocked by the read-only SQL compatibility view.

## Reset interaction and verification

Settings/data-management entry, away from ordinary actions. State: all cloud notes in all areas, temporary audio, any earlier saved local audio and drafts in this browser profile; global words/areas stay; other browsers keep local copies. Require exact `DELETE ALL NOTES`, red submit, Cancel default focus. Opening the dialog does nothing. Busy capture/model/save in the initiating tab must finish/cancel before reset; database/journal fences handle other tabs. Cloud success and local cleanup are separate confirmations. No Undo promise or test against real user content. The processing-status contract uses text-only durability semantics: new phase preparing_audio (RAM readiness/context checks), transcribing, saving_transcript (text-only persistence), saving_note (draft/library preparation). No new path uses saving_audio or recordingDurable for audio. Only textDurable controls transcript-save confirmation.

Required probes: old SQL INSERT/UPDATE/DELETE fails after migration; migration preserves notes/words; area name races/rename/archive/create replay; global+area chip input/IME/paste/sort/counts; RAM audio absent from all durable stores and gone after reload; text survives reload; legacy cleanup never silently deletes; reset vs queued writes/model/refine/read completion; lost response and old receipt after newer reset; two reset dialogs sharing one journal; same-profile cleanup failure; other-device offline material preserved read-only; current-generation post-reset note not cleared by a late receipt; vocabulary and areas unchanged byte-for-byte. Real browser IndexedDB and isolated libSQL transactions are required for these boundaries.
